# Working on PestM8

`main` **is production.** A commit landing on `main` deploys to the live app.
Everything here follows from that.

## The loop

```bash
git switch -c feat/short-description
# work
pnpm verify          # everything CI will check
git push -u origin feat/short-description
```

Open a pull request. CI runs. When it is green, **squash merge** it — one pull
request becomes one commit on `main`, which is what makes a rollback a single
`git revert`. The branch deletes itself.

Branch names: `feat/`, `fix/`, `chore/`, `docs/`. (`claude/…` is used by agent
sessions.)

Direct pushes to `main` are blocked. That is deliberate and it applies to
everyone, including whoever owns the repository.

## Commands

| Command         | Does                                                                |
| --------------- | ------------------------------------------------------------------- |
| `pnpm dev`      | Vite dev server on :3000 (needs `npx convex dev` alongside)         |
| `pnpm verify`   | Everything CI checks: format, lint, both typechecks, DST boundaries |
| `pnpm format`   | Fix formatting and auto-fixable lint                                |
| `pnpm build`    | Production build                                                    |
| `pnpm test:e2e` | Playwright suite (needs a dev server and a Convex deployment)       |
| `pnpm seed`     | Fill a dev deployment with a realistic business                     |

**pnpm only.** `packageManager` and `engines` in `package.json` pin the
toolchain; `.nvmrc` pins Node. Installing with npm will produce a different
dependency tree and no lockfile to match.

## Things that will bite you

**Don't run `tsr generate`.** `src/routeTree.gen.ts` is generated by the
TanStack Start Vite plugin during `pnpm dev` and `pnpm build`. The standalone
`@tanstack/router-cli` does not emit the `Register` declaration the committed
file carries, so running it silently strips SSR router typing while leaving
`tsc` green.

**`VITE_` variables are inlined at build time.** They are not read at runtime.
A build without them exits 0 and produces a bundle that throws on every page
load — which is why `scripts/check-env.mjs` gates the build.

**`SITE_URL` on a Convex deployment must exactly match the frontend origin.**
Better Auth rejects mismatched origins, and it presents as sign-in appearing to
succeed and then bouncing to `/login`.

**Local dev is HTTP; production is HTTPS.** Better Auth only adds the
`__Secure-` cookie prefix over HTTPS, so cookie-handling code that works
locally can fail in production. This has happened once already. Test anything
touching auth on the pull request's Vercel preview, not just locally.

## Schema changes

**Additive first.** Add optional fields; never rename or retype in one step.
Convex validates every existing document against the new schema at deploy time
and refuses the deploy if any row doesn't conform — so a breaking change fails
at deploy, but the recovery is a snapshot restore with data loss, not a revert.
See [docs/RUNBOOK.md](./docs/RUNBOOK.md).

## Tests

`e2e/access-control.spec.ts` is the suite that matters most — it asserts tenant
and role isolation at the Convex function level, not just in the UI
(ARCHITECTURE.md §6.5). It gates every pull request. The rest of the suite runs
nightly, on demand, or when you add the `run-e2e` label to a pull request.

Every negative case must be verified at the Convex function level. A hidden
button is not access control.

## Deploying

You don't. Merging to `main` does it. See [DEPLOYMENT.md](./DEPLOYMENT.md) for
how the environments are wired and [docs/RUNBOOK.md](./docs/RUNBOOK.md) for
when it goes wrong.
